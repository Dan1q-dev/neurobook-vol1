Задание 1. Признаки и метка опоздания

Расстояние, заявленная масса и обещанное время известны при оформлении. Из них можно построить признаки. После доставки сравниваем фактическое прибытие с обещанным. Метка равна 1 при строгом превышении срока, иначе 0. Прибытие точно в обещанное время относится к классу 0. Фактическое время здесь используется для разметки истории.

Метки для трёх случаев (Ответы/01-late-label.py)

promised = 720
arrivals = [710, 720, 735]
labels = [int(arrival > promised) for arrival in arrivals]
print("Метки опоздания", labels)

Результат

Метки опоздания [0, 0, 1]

Часы в примере записаны числом минут от начала одного дня. Обещанный срок 720 означает 12:00. Сравнение arrival > promised даёт логическое значение, а int превращает его в 0 или 1. Если доставка переходит на следующий день, сравнивать нужно полные дату и время.

Задание 2. Новые границы по дням

В train девять заказов 201-209. В validation четыре заказа 210-213. В test пять заказов 214-218. В нашем файле на каждый день приходится одна строка, поэтому число записей равно числу дней в диапазоне. Сумма 9 + 4 + 5 равна 18.

Проверка числа строк и номеров (Ответы/02-new-time-split.py)

import pandas as pd

orders = pd.read_csv("orders-quality.csv")
day = orders["day"]
parts = {
    "train": orders.loc[day <= 9],
    "validation": orders.loc[day.between(10, 13)],
    "test": orders.loc[day >= 14],
}
for name, part in parts.items():
    numbers = part["order_id"]
    print(name, len(part), numbers.min(), numbers.max())

Результат

train 9 201 209
validation 4 210 213
test 5 214 218

Задание 3. Повторяющийся клиент

Клиент 31 оформил заказы 201, 205, 211 и 217 в дни 1, 5, 11 и 17. При исходном делении по времени первые два попадают в train, 211 попадает в validation, 217 в test. При проверке на новом клиенте все четыре записи 31 должны быть в группе проверки. В отдельном упражнении на групповой отбор возьмём остальных клиентов как кандидатов для обучения. Если нужна и проверка на будущих датах, дополнительно ограничим обучающие дни.

Проверочная группа клиента 31 (Ответы/03-customer-holdout.py)

import pandas as pd

orders = pd.read_csv("orders-quality.csv")
is_31 = orders["customer_id"] == 31
held_out = orders.loc[is_31]
other = orders.loc[~is_31]

print("Заказы 31", held_out["order_id"].tolist())
print("Дни", held_out["day"].tolist())
print("Заказов клиента 31 у остальных",
      (other["customer_id"] == 31).sum())

Результат

Заказы 31 [201, 205, 211, 217]
Дни [1, 5, 11, 17]
Заказов клиента 31 у остальных 0

Знак ~ меняет True на False и наоборот в маске pandas. С помощью is_31 берём записи одного клиента, через ~is_31 получаем все остальные.

Во втором случае обучение содержит дни 1, 2 и 3. Модель уже видела клиентов А и Б. Дни 4 и 6 подходят для теста, потому что клиенты В и Г новые и оба заказа оформлены после обучения. День 5 тоже будущий, но клиент Б уже встречался. Этот заказ пригодится для отдельной проверки на повторных клиентах. В ответе должны быть указаны граница по времени и списки клиентов обеих частей.

Задание 4. Сравнение по двум метрикам

Ошибки A по модулю равны 2, 2, 2 и 2. Его MAE и RMSE равны 2. У B теперь ошибки 0, 0, 0 и 4. MAE равна 4 / 4 = 1, RMSE равна √(16 / 4) = 2. По MAE выигрывает B. По RMSE результаты равны. При равенстве по основной метрике можно заранее договориться выбирать более простое правило или смотреть согласованный дополнительный показатель.

Проверка после изменения прогноза (Ответы/04-new-regression-errors.py)

from math import sqrt

actual = [10, 15, 20, 25]
rules = {"A": [12, 13, 22, 23], "B": [10, 15, 20, 29]}
for name, predicted in rules.items():
    errors = [abs(p - y) for y, p in zip(actual, predicted)]
    mae = sum(errors) / len(errors)
    rmse = sqrt(sum(e ** 2 for e in errors) / len(errors))
    print(name, "ошибки", errors)
    print(f"MAE {mae:.2f}, RMSE {rmse:.2f}")

Результат

A ошибки [2, 2, 2, 2]
MAE 2.00, RMSE 2.00
B ошибки [0, 0, 0, 4]
MAE 1.00, RMSE 2.00

Задание 5. Базовая цена по пяти дням

Цены дней 1-5 после сортировки идут в порядке 5, 8, 11, 14 и 15. Число посередине равно 11, это медиана. На четырёх заказах validation модули отклонений равны 3, 8, 3 и 10. MAE равна 24 / 4 = 6. Ответы validation используются после выбора константы, чтобы посчитать ошибку.

Константа и её ошибка (Ответы/05-train-median.py)

import pandas as pd

orders = pd.read_csv("orders-quality.csv")
train = orders.loc[orders["day"] <= 5]
val = orders.loc[orders["day"].between(11, 14)]
constant = train["price"].median()
errors = (val["price"] - constant).abs()
print("Константа", constant)
print("Ошибки", errors.tolist())
print("MAE", errors.mean())

Результат

Константа 11.0
Ошибки [3.0, 8.0, 3.0, 10.0]
MAE 6.0

Задание 6. Одно пропущенное опоздание

TP = 1, FN = 1, FP = 1 и TN = 17. Значит, accuracy равна (1 + 17) / 20 = 0,90. Precision равна 1 / (1 + 1) = 0,50, recall равна 1 / (1 + 1) = 0,50, F1 равна 2 / (2 + 1 + 1) = 0,50. Правило «всегда 0» тоже даёт 0,90 по accuracy, но при нём пропущены оба опоздания.

Проверка новых предупреждений (Ответы/06-late-metrics.py)

actual = [1, 1] + [0] * 18
predicted = [1, 0, 1] + [0] * 17
matrix = [[0, 0], [0, 0]]
for answer, prediction in zip(actual, predicted):
    matrix[answer][prediction] += 1

tn, fp = matrix[0]
fn, tp = matrix[1]
print("TN, FP, FN, TP", tn, fp, fn, tp)
print(f"Accuracy {(tn + tp) / len(actual):.2f}")
print(f"Precision {tp / (tp + fp):.2f}")
print(f"Recall {tp / (tp + fn):.2f}")
print(f"F1 {2 * tp / (2 * tp + fp + fn):.2f}")

Результат

TN, FP, FN, TP 17 1 1 1
Accuracy 0.90
Precision 0.50
Recall 0.50
F1 0.50

Задание 7. Стоимость ложных предупреждений и пропусков

У исходной модели три ложных предупреждения и ноль пропусков. Стоимость 3 × 1 + 0 × 5 = 3. У модели из задания 6 одно ложное предупреждение и один пропуск, итог 6. У правила «всегда 0» нет предупреждений и есть два пропуска, итог 10. При заданных издержках на этих 20 заказах исходная модель даёт наименьшую стоимость.

Сравнение по издержкам (Ответы/07-error-cost.py)

counts = {
    "Исходная модель": (3, 0),
    "Модель из задания 6": (1, 1),
    "Всегда 0": (0, 2),
}
for name, (fp, fn) in counts.items():
    cost = fp + 5 * fn
    print(name, cost)

Результат

Исходная модель 3
Модель из задания 6 6
Всегда 0 10

Задание 8. Разбор ошибки по типу заказа

Обычные заказы 215 и 218 дали ошибки 1 и 1, их MAE равна 1. Срочные 216 и 217 дали ошибки 1 и 3, их MAE равна 2. В каждой группе всего два заказа. Один заказ 217 заметно влияет на среднее. Вывод для этого опыта ограничен этими четырьмя заказами. Для уверенного сравнения типов нужно собрать больше новых примеров каждого типа и снова оценить зафиксированное правило.

Проверка двух групп на тесте (Ответы/08-errors-by-service.py)

import pandas as pd

orders = pd.read_csv("orders-quality.csv")
test = orders.loc[orders["day"] >= 15].copy()
express = test["service"] == "express"
predicted = 3 * test["distance_km"] + 2 + express * 4
test["error"] = (test["price"] - predicted).abs()
for service in ("standard", "express"):
    group = test.loc[test["service"] == service, "error"]
    print(service, "заказов", len(group), "MAE", group.mean())

Результат

standard заказов 2 MAE 1.0
express заказов 2 MAE 2.0

Надбавку 4 берём из уже проверенного расчёта на train. Метод copy создаёт отдельную таблицу, в которую добавляем столбец ошибок. Затем для каждого типа выбираем его строки и берём среднее модулей. Общая MAE равна (1 + 1 + 1 + 3) / 4 = 1,5.

Задание 1. Тип и форма меток

Передаём столбец из 1,0 и 0,0. Для первого заказа вероятность p₁ = 0,5 и потеря -ln(p₁) ≈ 0,693147. Для второго p₂ ≈ 0,222700 и потеря -ln(1 - p₂) ≈ 0,251929. Средняя потеря около (0,693147 + 0,251929) / 2 = 0,472538. Метод float() приводит метки к float32, а unsqueeze(1) добавляет ось столбцов.

Подготовка меток для BCEWithLogitsLoss (Ответы/01-target-shape.py)

import torch
from torch import nn

z = torch.tensor([[0.0], [-1.25]])
labels = torch.tensor([1, 0])
y = labels.float().unsqueeze(1)
print("До", tuple(labels.shape), labels.dtype)
print("После", tuple(y.shape), y.dtype)
criterion = nn.BCEWithLogitsLoss()
loss = criterion(z, y)
print(f"Средняя потеря {loss.item():.6f}")

Результат

До (2,) torch.int64
После (2, 1) torch.float32
Средняя потеря 0.472538

Задание 2. Накопление градиентов

Один вызов backward даёт градиент -6, два дают -12. При очистке перед новым шагом вес станет 2 - 0,1 × (-6) = 2,6, потеря (3 × 2,6 - 7)² = 0,64. Если использовать накопленное значение -12, вес станет 3,2, потеря (3 × 3,2 - 7)² = 6,76. В этой задаче лишний градиент удвоил шаг и перенёс вес слишком далеко.

Два шага из одного начального веса (Ответы/02-clear-gradient.py)

import torch

w = torch.tensor(2.0, requires_grad=True)
for steps in (1, 2):
    w.grad = None
    for _ in range(steps):
        ((3 * w - 7) ** 2).backward()
    with torch.no_grad():
        new_w = w - 0.1 * w.grad
        new_loss = (3 * new_w - 7) ** 2
    print(f"Вызовов {steps}, градиент {w.grad.item():.1f}")
    print(f"Новый вес {new_w.item():.1f}, потеря {new_loss.item():.2f}")

Результат

Вызовов 1, градиент -6.0
Новый вес 2.6, потеря 0.64
Вызовов 2, градиент -12.0
Новый вес 3.2, потеря 6.76

Задание 3. Обратный проход при метке 0

Без обновления весов вероятность остаётся 0,5. Производная потери по логиту теперь p - y = 0,5. Для выходных весов умножаем 0,5 на скрытые значения 1 и 0, для выходного смещения берём 0,5. Для первого скрытого нейрона сигнал равен 0,5 × 1 = 0,5. У второго ReLU закрыт, его градиенты нулевые. Умножаем 0,5 на входы 2 и 1 и получаем 1 и 0,5. В nn.Linear у веса от второго входа к первому скрытому нейрону индекс [0, 1].

Градиенты слоёв при новой метке (Ответы/03-zero-label.py)

import torch
from torch import nn

model = nn.Sequential(nn.Linear(2, 2), nn.ReLU(), nn.Linear(2, 1))
with torch.no_grad():
    model[0].weight.copy_(torch.tensor([[0.5, 1.0], [-0.5, -0.5]]))
    model[0].bias.copy_(torch.tensor([-1.0, 0.5]))
    model[2].weight.copy_(torch.tensor([[1.0, -1.0]]))
    model[2].bias.fill_(-1.0)
z = model(torch.tensor([[2.0, 1.0]]))
criterion = nn.BCEWithLogitsLoss()
loss = criterion(z, torch.tensor([[0.0]]))
loss.backward()
print("Первый слой", model[0].weight.grad.tolist(),
      model[0].bias.grad.tolist())
print("Выходной слой", model[2].weight.grad.tolist(),
      model[2].bias.grad.tolist())
print("Вес [0, 1]", model[0].weight.grad[0, 1].item())

Результат

Первый слой [[1.0, 0.5], [0.0, 0.0]] [0.5, 0.0]
Выходной слой [[0.5, 0.0]] [0.5]
Вес [0, 1] 0.5

Задание 4. Разный размер пакетов

Суммарная потеря по пяти строкам равна 2 × 0,2 + 2 × 0,4 + 1 × 0,8 = 2. Делим на 5 и получаем 0,4. Простое среднее (0,2 + 0,4 + 0,8) / 3 ≈ 0,466667 даёт слишком большой вклад одиночной строке.

Средняя по строкам и средняя по пакетам (Ответы/04-average-loss.py)

sizes = [2, 2, 1]
means = [0.2, 0.4, 0.8]
total = sum(size * mean for size, mean in zip(sizes, means))
print(f"По строкам {total / sum(sizes):.6f}")
print(f"По пакетам {sum(means) / len(means):.6f}")

Результат

По строкам 0.400000
По пакетам 0.466667

Задание 5. Логит и сигмоида

Для правильной метки 1 и логита 0 получаем -ln(0,5) ≈ 0,693147. Когда передаём вероятность 0,5, функция воспринимает её как логит и внутри расчёта использует сигмоиду от 0,5, то есть примерно 0,622459. Потеря уменьшается до 0,474077 из-за подмены входа функции. Прогноз исходной модели был 0,5.

Что происходит при повторной сигмоиде (Ответы/05-logits-vs-probabilities.py)

import torch
from torch import nn

z, y = torch.tensor([[0.0]]), torch.tensor([[1.0]])
criterion = nn.BCEWithLogitsLoss()
print(f"Подали логит {criterion(z, y).item():.6f}")
print(f"Подали вероятность {criterion(torch.sigmoid(z), y).item():.6f}")

Результат

Подали логит 0.693147
Подали вероятность 0.474077

Задание 6. Проверка Dropout

При обучении каждое сохранённое значение равно 1 / (1 - 0,25) = 4 / 3. В eval все восемь значений равны 1 и сумма равна 8. В этом примере выход сохраняет requires_grad=True, если выполняем eval с обычной записью операций. Внутри inference_mode получаем requires_grad=False при обычных операциях. Dropout в eval может напрямую вернуть вход, поэтому в коде берём сумму внутри блока, чтобы проверить флаг у результата новой операции.

Dropout с другой вероятностью (Ответы/06-check-dropout.py)

import torch
from torch import nn

torch.manual_seed(7)
layer = nn.Dropout(0.25)
x = torch.ones(8, requires_grad=True)
active = layer(x)
nonzero = active[active != 0]
print("Значения train", sorted({round(v, 6) for v in nonzero.tolist()}))
layer.eval()
total = layer(x).sum()
with torch.inference_mode():
    checked = layer(x).sum()
print("eval", total.item(), total.requires_grad)
print("eval и inference_mode", checked.item(), checked.requires_grad)

Результат

Значения train [1.333333]
eval 8.0 True
eval и inference_mode 8.0 False

Задание 7. Лучшая эпоха из таблицы

По валидации сохраняем эпоху 62 с потерей около 0,386372. На эпохе 120 обучающая потеря уменьшилась примерно на 0,017807, а валидационная выросла примерно на 0,005893. Сортировать таблицу целиком не нужно. Функция min проходит по строкам и сравнивает их по val_loss, преобразованной в число. Файл содержит значения из проверочного запуска примера 07.

lambda row: float(row["val_loss"]) обозначает короткую функцию без имени. Она получает строку и возвращает её потерю числом. min использует это число как критерий сравнения строк.

В отдельном опыте на рисунке минимум на эпохе 12. Падение train с 0,4007 до 0,0013 сопровождается ростом val с 0,4874 до 2,1993. На заказах рост val намного меньше, а валидация состоит из восьми строк. Это даёт более слабое свидетельство.

Проверка лучшей и последней строк (Ответы/07-find-best-epoch.py)

from csv import DictReader

with open("learning-curve.csv", encoding="utf-8", newline="") as file:
    rows = list(DictReader(file))
best = min(rows, key=lambda row: float(row["val_loss"]))
for row in (best, rows[-1]):
    train = float(row["train_loss"])
    val = float(row["val_loss"])
    print(f"Эпоха {row['epoch']}, train {train:.6f}, val {val:.6f}")

Результат

Эпоха 62, train 0.414776, val 0.386372
Эпоха 120, train 0.396969, val 0.392265

Задание 8. Прогнозы пакетом и по одному

После деления расстояний на 2 получаем строки [2, 1] и [1, 1]. Каждый заказ проходит сеть независимо. torch.allclose сравнивает числа с небольшим допуском, поскольку порядок вычислений может повлиять на округление. Вероятности около 0,707615 и 0,118918. При пороге 0,5 классы 1 и 0.

Два одинаковых способа получить прогноз (Ответы/08-predict-two-orders.py)

import torch
from torch import nn

saved = torch.load("delivery-ch10.pt", map_location="cpu", weights_only=True)
width = saved["hidden_size"]
model = nn.Sequential(nn.Linear(len(saved["columns"]), width),
                      nn.ReLU(), nn.Linear(width, 1))
model.load_state_dict(saved["state_dict"])
model.eval()
orders = [{"distance_km": 4.0, "rush": 1.0},
          {"distance_km": 2.0, "rush": 1.0}]
for order in orders:
    order["distance_km"] /= saved["scale"]
X = torch.tensor([[order[name] for name in saved["columns"]] for order in orders])
with torch.inference_mode():
    all_at_once = torch.sigmoid(model(X)).flatten()
    one_by_one = torch.cat([torch.sigmoid(model(row[None])) for row in X]).flatten()
print("Вероятности", [round(p, 6) for p in all_at_once.tolist()])
print("Совпадают", torch.allclose(all_at_once, one_by_one))
print("Классы", (all_at_once >= saved["threshold"]).int().tolist())

Результат

Вероятности [0.707615, 0.118918]
Совпадают True
Классы [1, 0]
